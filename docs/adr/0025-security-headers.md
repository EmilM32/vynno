# ADR-0025: Security response headers

**Status:** Accepted  
**Date:** 2026-09-11  
**Deciders:** Project owner

## Context

QA step SEC-11 (2026-09-11) scanned the response headers of the local production FE and found none of the usual baseline: no `Content-Security-Policy`, no `X-Frame-Options` and no CSP `frame-ancestors`, no `Referrer-Policy`, no `X-Content-Type-Options`. The rest of the defensive battery (SEC-1…SEC-9 — cookie flags, CSRF origin check, CORS, IDOR, revocation) passed, so this was the one hardening gap.

The app makes a strict policy unusually cheap. Nothing loads cross-origin: fonts are self-hosted ([`src/lib/theme/fonts.css`](../../src/lib/theme/fonts.css) — Google Fonts is contacted only by the build-time `scripts/fetch-fonts`), there is no analytics or CDN, `static/` holds only `robots.txt`, and the API is same-origin through the `/v1` BFF ([0012](./0012-env-origins.md)). Avatars are already rewritten to same-origin paths in `src/lib/api/mappers/profile.ts`.

Three things did make a naive policy risky:

- SvelteKit injects an inline hydration script on every SSR render.
- `src/app.html` has one hand-written inline script — the anti-FOUC theme bootstrap.
- `src/error.html` ([0019](./0019-error-pages.md)) is a standalone shell with two inline `<script>` blocks and a large inline `<style>`. It is served outside the normal render path, so nothing hashes it.

## Decision

1. **The CSP is generated by SvelteKit**, via `kit.csp` in `svelte.config.js`, in **`nonce` mode. Kit nonces its own hydration script; `src/app.html` opts in with `<script nonce="%sveltekit.nonce%">`. Nonce over hash because every route is server-rendered — `grep -rn prerender src/` is empty — and hashes would have to be recomputed on every inline-script edit.
2. **The CSP is set only on Kit page renders.** It is deliberately _not_ set at the edge, because a blanket CSP would break `src/error.html`, which Kit's CSP machinery cannot hash.
3. **The constant headers live in the app**, in `src/lib/server/security-headers.ts`, applied by `handleSecurityHeaders` as the outermost hook in `src/hooks.server.ts`:

   | Header                   | Value                                                                  |
   | ------------------------ | ---------------------------------------------------------------------- |
   | `Referrer-Policy`        | `strict-origin-when-cross-origin`                                      |
   | `X-Content-Type-Options` | `nosniff`                                                              |
   | `X-Frame-Options`        | `DENY` (legacy backstop; `frame-ancestors 'none'` is the real control) |

   The app layer is the primary one because it is the only one present in all three run modes — daily Node, `scripts/run-node`, and the `vite preview` that Playwright drives — which makes the headers testable (`e2e/security-headers.spec.ts`).

4. **The same three constants are repeated in `Caddyfile`.** adapter-node serves `/_app/immutable/*` through `sirv`, which never reaches `hooks.server.ts`, so Node stamps documents but not static assets. Caddy closes that gap for the daily URL. Values are identical and Caddy _sets_ rather than appends, so no header is duplicated. The CSP is not repeated there — see clause 2.
5. **`style-src` keeps `'unsafe-inline'`, and `style-src-attr 'unsafe-inline'` is spelled out.** Svelte and LayerChart set inline `style=` attributes, and `src/app.html` uses `style="display: contents"`. `style-src-attr` is explicit so attributes keep working even if Kit later adds a nonce to `style-src` — a nonce makes `'unsafe-inline'` ignored.
6. **No `Strict-Transport-Security`.** The daily origin is `https://vynno.localhost`; HSTS there pins _every_ `*.localhost` origin to HTTPS in the browser for the whole `max-age`, breaking unrelated local projects. Revisit only for a real deployed hostname.

## Consequences

### Positive

- Clickjacking, MIME-sniffing, and referrer leakage are closed, and the CSP forbids any cross-origin script, style, font, image, or connection.
- The policy is asserted, not assumed: 6 Vitest cases plus 5 Playwright cases, the first header coverage in the repo.
- `error.html` keeps working, because no CSP is applied at the edge.

### Negative / tradeoffs

- `style-src 'unsafe-inline'` is a real weakening. Removing it means dropping `style="display: contents"` from `app.html` and auditing LayerChart's inline styles; not worth it for the benefit today.
- The three constants exist in two places (hooks and Caddy). They are identical and both are asserted, but an edit must touch both.
- `npm run dev` reports a laxer policy than production: Kit strips nonces and injects `'unsafe-inline'` in dev. Assert headers against the preview or the daily build, never the Vite dev server.

## Alternatives considered

| Option                                      | Why not                                                                                                                                                              |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| All headers in Caddy only                   | Invisible to `vite preview` and `scripts/run-node`, so untestable by Playwright and absent from two of three run modes. A blanket CSP would also break `error.html`. |
| CSP in `hooks.server.ts` by hand            | Would have to reproduce Kit's nonce for the hydration script. `kit.csp` already owns it.                                                                             |
| `mode: 'hash'`                              | Hashes must be recomputed whenever an inline script changes; no prerendered routes to justify it.                                                                    |
| `Content-Security-Policy-Report-Only` first | No external origins to discover and no report collector on this machine; the e2e specs already assert a violation-free console.                                      |
| Add HSTS for completeness                   | Poisons every other `*.localhost` project on the machine.                                                                                                            |
